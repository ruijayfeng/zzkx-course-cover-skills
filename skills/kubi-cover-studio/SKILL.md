# 枯笔写意课程封面工作室

将用户指定的课程制作成内容对应准确、系列风格延续的封面。用户决定采用什么画面；你负责课程核对、方案整理、生图执行、检查与归档。使用简洁中文交流，向用户展示画面内容和取舍，不先展示生成提示词。

## 1. 接收课程并核对原文

- 输入可以是编号、课名或一组课程。按本包 [课程大纲](references/course-outline.md) 查明编号、课名、分类、重点和易错；可运行 `python3 scripts/lookup_course.py --id 431`（脚本路径按本 Skill 所在位置解析）。准确课名也可用 `--name` 查询。
- 默认工作目录为当前用户工作区内的 `course-covers/kubi/`；已指定目录则沿用。按 [资产规范](references/assets-and-state.md) 创建本课记录。Skill 安装目录只读，实际资产写入用户工作区。
- 重做清单由用户另行提供，本包不固化待重做课程。旧图、旧 FINAL、旧 QA 均是历史材料，不能据此声称用户认可。用户已明确否定的内容不作为成功案例。
- 编号与名称冲突、缺少关键教学材料或原文自相矛盾时，指出具体疑点并只澄清受影响课程。用户提供新版大纲时保留版本来源；不擅自改写课程事实。范围外课程说明所属风格，需要中阶时转用对应 Skill，不能按高阶事实生成。
- 初次使用读取 [内容设计](references/content-design.md) 和 [风格规范](references/style-profile.md)。本包流程不自动继承旧批次冻结、PLAN次数及历史重做名单；目标工作区的有效指令仍适用，冲突应明说，不能静默绕过。

完成条件：课程事实与输出位置清楚，尚未调用生图。

## 2. 给出可选择的文字方案

先用一两句说明本课实际教什么，再提供通常 2–3 个有实质区别的画面方案。按内容设计规范写：主体、动作或关系、必要环境与构图、和课程的直接联系、表达边界。质量不足时少给方案，不用牵强比喻凑数量。

每轮明确告诉用户：**“你可以选一个方案，也可以组合或修改；如果都不合适，直接大概描述你想要的画面，我会结合课程内容整理后再请你确认。”** 保存本轮方案及课程对应依据，状态为 `AWAITING_DIRECTION`，等待用户输入。

## 3. 整理用户方向并确认

- 用户自述、组合或修改时，先保留原话，再把想法整理为完整画面。给出与你理解一致的主体、动作、关系和构图，并解释课程对应。只有影响内容的歧义才提问；用户无需懂构图或提示词。
- 描述与课程存在偏差时，具体指出偏差，给出保留用户意图的修正方案；不能把偏差藏在提示词里。用户明确选用装饰性主题时记录其边界，不声称它准确示教了书写规律。
- 展示最终方案摘要和版本，请用户确认。记录用户真实回复、确认的方案版本与范围，状态为 `CONFIRMED` 后才可调用生图。选择初稿不等于同意你后来增加的内容。
- 若用户已经对展示完整的方案明确说“就按A出图”等，直接记录为确认，无需重复询问。仅“选A”、初始“做这门课”或未回复，不自动确认后续整理版。
- 内容改变后回到确认；只把已确认内容翻译成生成提示词不需再问。多课分别记录确认，不把单课确认扩展到其他课程。

完成条件：工作区内有可定位的确认方案和用户确认记录。没有确认时，本轮交付文字方案即可，不调用图像工具。

## 4. 确认后生成

读取 [生成与检查](references/generation-and-review.md)。查看本包三张风格参考原图，记录纸色、色彩、笔触、空间的借鉴；参考图只承担风格校准，内容沿用已确认方案。

按“确认内容＋风格描述＋构图＋必要排除项”写实际提示词，使用当前环境可用的图像生成工具生成一张。默认沿用纯文字生图；用户明确要求图像参考、编辑或指定数量时，按其范围执行。先保存提示词、确认版本与调用记录，再调用工具；返回后立即保存原图并检查，完成本课后再处理下一张。

## 5. 检查、交付与续做

检查原图、320px缩图及三参考并排图：内容是否执行确认方案，16:9比例、暖白生宣、黑灰墨色、枯笔飞白、断墨和压力变化是否延续；同时检查主体辨识、人物完整性、题字空间、意外文字。逐项留下可观察证据，自动尺寸结果不能代替视觉判断。

按检查规范归档：通过项复制到 `final/` 并展示给用户；不通过项保留原图和问题，给出下一步建议，不擅自连续重生。用户后续修改进入对应环节，所有版本与反馈保留。回复附本课资产目录、最终图或待决事项，更新状态；不能把 Skill 自检通过写成用户已验收。
